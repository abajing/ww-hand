WW-HAND —— 本机这份副本怎么用
================================================================

完整说明看 README.zh-CN.md（中文）和 README.md（英文）。
本文件只讲「本机这份」跟通用说明不一样的地方。

一、它现在是个独立实例
----------------------------------------------------------------

    端口      8794        （另一个实例是 8792）
    实例名    fuse1       （另一个实例是空）
    根目录    本文件夹

三个 .bat 入口已经把这套变量设好了，双击即用，不用记命令：

    启动.bat     提权拉起守护，等 8794 应答，打印 pid / build / instance
    停止.bat     只停本副本（按完整路径匹配进程），并确认 8794 不再应答
    状态.bat     看本副本状态；顺便只读看一眼 8792 在不在
    测试.bat     跑 31 项断言（会启动记事本做文本输入往返，属正常）

两套可以同时跑，互不干扰。

二、改代码之前
----------------------------------------------------------------

源文件里的路径已经是「按文件位置自动推导」的，不再写死盘符。
但环境变量仍然优先，所以 .bat 里设的 WW_PORT / WW_INSTANCE 会覆盖默认值。

改完必须换手，否则跑的还是旧代码：

    停止.bat   →   启动.bat

换完要验 build —— 只看 pid 变了不够。reset 实测只杀到守护的 launcher，
真正的守护靠互斥体收敛，pid 变了不代表新文件加载了。要读 /health 的 build 字段：

    状态.bat   里会打出来

改完跑 测试.bat，确认 31 项还绿。

三、解释器
----------------------------------------------------------------

_ops\python.txt 里一行，写 python.exe 的完整路径。
启动器和 .bat 都从这里取，所以换 Python 环境只改这一个文件。

这个文件是机器相关的，不进 git（.gitignore 里排掉了）。
没有它的时候，.bat 会退回用 PATH 上的 python.exe。

四、入库状态
----------------------------------------------------------------

    .gitignore        排掉 _ipc / _log / _shots / _state / __pycache__ / python.txt
    LICENSE           MIT
    requirements.txt  依赖（uiautomation / comtypes / Pillow / numpy；
                      rapidocr 是可选，装上有 OCR，没装 ocr.py 会明确报错）
    README.md         英文主文档
    README.zh-CN.md   中文主文档
    清单.md5          所有静态文件的 md5，日后核对有没有被改

_ops\start-hand.vbs、四个 .bat 都是纯 ASCII，这是故意的：
cmd.exe 和 wscript 按 OEM 代码页读文件，里面写 UTF-8 中文会整行乱码。

五、边界（别在这上面耗时间）
----------------------------------------------------------------

    PostMessage 打不进 Raw Input / DirectInput 程序（大部分游戏）。
    UIA 看不见 Unity / UE 游戏窗口内部。
    两条都要签名内核驱动，用户态无解。
